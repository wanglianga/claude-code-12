# 高校实验室危险试剂领用与废液回收平台

## 原始需求

> 增加跨课题组借用试剂的风险审批。某个课题组临时缺少试剂时，平台允许向同楼层实验室发起借用申请，但会先比较试剂危险等级、开封日期、保存条件、借用量和双方导师权限。借出方同意后，安全员确认转移路线和交接时间；若借用后产生废液，废液责任仍要拆回实际使用项目，防止借用记录和废液记录分离。审批结果会同步到库房发放和废液责任人，安全员后续复盘时可以判断风险来自借用本身、转移过程还是实际使用。

## 平台简介

面向高校实验室的危险试剂「申请 → 审批 → 出库 → 使用 → 废液 → 转运」全链路闭环管理系统。
平台自动判定试剂危险类别（易制毒 / 易制爆 / 剧毒 / 强腐蚀 / 低温保存），串联导师、实验室安全员、库管、学院审核四类责任角色，并对「用量超申请、通风橱故障、试剂过期、废液桶将满、异常洒漏」自动生成异常工单转安全员复核，确保试剂领走后最终回到废弃物处置链路，不停留在台账。

在既有领用闭环之上，平台新增**跨课题组借用试剂风险审批**：课题组临时缺料时可向同楼层实验室发起借用，系统先比较试剂危险等级、开封日期、保存条件、借用量与双方导师权限，经双方导师与安全员（转移路线/交接时间）审批后办理「组间余流发放」与现场交接；借用试剂产生的废液责任拆回实际使用项目/课题组，安全员复盘时可按「借用本身 / 转移过程 / 实际使用」三来源归因。

## 技术栈

- **前端**：Vue 3 + Vite + Element Plus + Pinia + Vue Router（nginx 非 root 镜像提供静态服务并反向代理 `/api`）
- **后端**：NestJS 10 + TypeORM + JWT 鉴权（角色守卫）
- **数据库**：PostgreSQL 16（首次启动自动建表并注入演示数据）

## 快速开始（Docker 一键部署）

```bash
cp .env.example .env        # 按需修改端口/密钥
docker compose up -d --build
```

启动后访问：`http://localhost:${CC_PUBLISH_PORT}`（`.env` 中的 `CC_PUBLISH_PORT`，示例为 3012）。

- 仅前端端口发布到宿主机；PostgreSQL 与后端仅在 compose 内部网络互访。
- 首次启动自动完成建表与演示数据初始化（`SEED_DEMO=false` 可关闭）。
- 验证方式：宿主机执行 `docker compose up -d`，待 `docker compose ps` 全部 healthy 后，
  用 `docker compose port frontend 8080` 获取映射端口，浏览器访问 `http://localhost:<端口>`。

## 一条建议的端到端演示流程

1. `zhangsan` 登录 → 新建领用申请（选「丙酮」，自动判定易制毒、双人领取、限量 500ml）。
2. `wangprof` 登录 → 审批中心 → 同意（确认实验必要性）。
3. `safety` 登录 → 申请详情 → 查看自动预检（培训记录/有效库存）→ 勾选五项核查、指定通风橱 → 批准。
4. `keeper` 登录 → 申请详情 → 选择批次出库（批号/余量/有效期/开封/双人领取人）。
5. `zhangsan` 登录 → 使用登记（实际用量填超过申请量可触发异常；可勾选通风橱故障）。
6. `keeper` 登录 → 申请详情 → 废液入库（自动匹配原试剂与项目，选桶、填容器标签；桶液位 ≥90% 自动预警）。
7. `keeper` 登录 → 转运单 → 勾选已入库废液 → 填危废公司/称重/交接照片 → 提交学院审核。
8. `college` 登录 → 转运单 → 审核通过 → 申请单状态变为「已闭环」。
9. `safety` 登录 → 异常处理 → 查看链路闭合情况并填写处理结论。
10. 工作台 → 责任视图：按学院 / 课题组 / 库房 / 危险等级查看闭环率与未处理异常。

## 跨课题组借用端到端演示流程

1. `sunqi`（高分子305）登录 → 试剂借用 → **发起跨组借用**：仅能看到同楼层、他组、有效暂存试剂；选择 301 的「硫酸（已开封）」，实时显示五要素风险比较（危险等级 / 开封日期 / 保存条件 / 借用量 / 双方导师权限 + 同楼层），高风险但无阻断可提交。
2. 选择 301「氢氟酸」时风险预览为**极高风险·禁借**（剧毒），提交按钮禁用且服务端拒绝；用 `lisi`（仅强腐蚀）借丙酮则提示**借入方资质不足**被阻断。
3. `zhaoprof`（借入方导师）→ 试剂借用 → 确认实验必要性与本组资质。
4. `wangprof`（借出方导师）→ 同意让出本组暂存试剂。
5. `safety` → 填写**转移路线**（301→三层走廊→305，不走客梯）、**防泄漏转运容器**、**交接时间/地点** → 准予发放。
6. `keeper` → 办理**组间余流发放**（易制毒须填第二领取人）：系统扣减借出组暂存、同步库房发放台账，并自动生成归属「高分子·实际使用项目」的使用单。
7. `keeper`/`safety` → **现场交接**：双方签字（危险试剂双人）；若填写「瓶盖渗漏」等问题，自动生成**转移过程**风险事件。
8. `sunqi` → 实际使用登记（使用量 / 余量归还 / 废液类型与量 / 洒漏），超量或洒漏自动生成**实际使用**风险事件。
9. `keeper` → 借用废液入库：系统强制把**废液责任拆回实际使用项目/高分子课题组**，试剂来源「有机合成」仅留痕，防止借用记录与废液记录分离。
10. `safety` → 复盘：选择风险来自 **借用本身 / 转移过程 / 实际使用** 并填写结论后闭环；工作台「跨组借用风险复盘」三来源面板与 `/borrow/review-board` 汇总全部风险事件归因。

```
├── .env.example
├── backend/                  # NestJS：实体/鉴权/申请/库存/借用/废液/转运/异常/看板/种子数据

```

## 主要 API（前缀 `/api`）

- `POST /auth/login` 登录；`GET /dashboard/summary`、`GET /dashboard/responsibility?dim=college|group|warehouse|danger` 责任视图
- `POST /requisitions` 学生申请（自动判定危险类别）；`GET /requisitions/:id/chain` 全链路视图
- `POST /requisitions/:id/advisor-decision` 导师审批；`POST /requisitions/:id/safety-decision` 安全员审批（服务端复核培训与库存）
- `POST /requisitions/:id/dispense` 库管出库（事务+行锁，校验限量/双人/有效期）；`POST /requisitions/:id/usage` 使用登记（触发异常）
- `POST /waste/requisitions/:id/store` 废液入库（匹配试剂/项目/标签，桶液位预警；借用单废液责任拆回实际使用课题组）；`POST /waste/manifests` 转运单；`POST /waste/manifests/:id/review` 学院审核闭环
- `GET /anomalies` 异常工单（含借用本身/转移过程/实际使用三类借用风险事件）；`POST /anomalies/:id/resolve` 安全员处理
- 跨课题组借用：
  - `GET /borrow/new-options` 同楼层可借暂存与借入方导师；`POST /borrow/risk-preview` 五要素风险预研判；`POST /borrow` 发起借用（硬阻断服务端复核）
  - `POST /borrow/:id/borrower-advisor-decision` 借入方导师确认；`POST /borrow/:id/lender-advisor-decision` 借出方导师同意
  - `POST /borrow/:id/safety-decision` 安全员确认转移路线/转运容器/交接时间地点
  - `POST /borrow/:id/dispense` 库管「组间余流发放」（扣暂存+同步库房发放台账+生成实际使用单）；`POST /borrow/:id/handover` 现场双方交接（问题转转移过程风险事件）
  - `POST /borrow/:id/usage` 实际使用登记；`POST /borrow/:id/review` 安全员三来源复盘闭环
  - `GET /borrow/review-board` 风险三来源（借用本身/转移过程/实际使用）复盘看板；`GET/POST /borrow/stocks` 课题组暂存库存
